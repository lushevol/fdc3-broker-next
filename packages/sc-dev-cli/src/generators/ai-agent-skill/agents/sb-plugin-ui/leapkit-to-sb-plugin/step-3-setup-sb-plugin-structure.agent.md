# Step 3 — Set Up SB Plugin Project Structure

## Role

You are scaffolding a new Service Bench UI plugin project using the official `@scdevkit/cli` generator, then customising the generated output to match the routes, prefix, and API shape identified in the Migration Inventory (Step 1).

All values (plugin name, prefix, routes) come from the Step 1 inventory. **Derive them from the actual files — never hard-code.**

---

## Autonomous Execution Rules

- ✅ Run `@scdevkit/cli` immediately — do not manually create files that the CLI generates
- ✅ Answer CLI prompts using values derived from `_leapkit-archive/package.json` and the Step 1 inventory
- ✅ Apply post-scaffold customisations to routes, constants, and API service without asking
- ✅ Run `npm install` after the CLI finishes (the CLI may not run it automatically)
- ❌ NEVER delete files generated by the CLI — only modify them
- ❌ NEVER skip post-scaffold steps — partial customisation breaks the plugin build
- ❌ NEVER use the `@sc-sb-project/` scoped name anywhere other than `package.json` and azure-pipeline yaml files — it must not appear in TypeScript/JavaScript imports or any other source file

## Step 3C — Post-Scaffold Customisation

Apply the following changes to the CLI-generated files. These replace placeholder values with the actual project data from the Step 1 Migration Inventory.

### 1. `manifests/routes.json` — Replace placeholder routes

The CLI generates a single example route. Replace the entire `routes` array and `headerDefinition` with entries derived from `_leapkit-archive/src/App.js` (`<SimpleView>`) and `_leapkit-archive/src/config.json` (`navigationItems`):

```json
{
  "routes": [
    // One entry per SimpleView — derive path, component tag, and element from Step 1 inventory
    { "path": "[feature]", "component": "[prefix]-[feature]", "element": "[feature].js" }
  ],
  "headerDefinition": {
    "title": "[title]", // From config.json
    "showHeader": true,
    "menus": [
      // Translate navigationItems — flat entries with href:
      { "title": "[Label]", "href": "[path]" }
      // Guarded items are shown conditionally via protect-plugin (see Step 5)
    ]
  }
}
```

**routes.json rules:**
- Parent dropdown entries with `menuItems` do NOT have `href`
- Flat entries need `href`
- Path params use `:paramName` syntax
- **Optional path parameters:** React Router's `/:param?` question-mark suffix is not valid in `routes.json`. Declare two explicit routes sharing the same component and element file — one without the param and one with. Add `{/}?` at the end of each path to also handle the trailing-slash variant:
  ```json
  { "path": "details/:type{/}?",      "component": "[prefix]-details", "element": "details.js" },
  { "path": "details/:type/:id{/}?",  "component": "[prefix]-details", "element": "details.js" }
  ```
  The component checks `navigation.params?.id` and treats `undefined` as absent.

### 2. `src/constants/app.ts` — Set plugin prefix and event prefix

Update (or create if absent) with values from the Step 1 inventory:

```typescript
/** Custom element tag prefix, e.g. "sb-go-url" → tags like "sb-go-url-home" */
export const PLUGIN_PREFIX = '[derived-prefix]';

/** Event prefix for all CustomEvents dispatched in this plugin */
export const EVENT_PREFIX = '[derived-prefix]-';
```

Rules for deriving the prefix:
- Take the scoped package name from `package.json` (e.g. `@sc-sb-project/go-url` → `go-url`) — the `@sc-sb-project/` scope exists only in `package.json` and azure-pipeline yaml files and must not be used anywhere else
- Prepend `sb-` to the unscoped part to form the custom element tag prefix (e.g. `go-url` → `sb-go-url`)
- All custom events share the same prefix (e.g. `sb-go-url-link-selected`)

### 4. `src/api/ApiService.ts` — Add REST client wrapper

If the original project used `HttpService` REST calls (not GraphQL), add this file **alongside** any `GraphQLClientService` the CLI may have generated:

```typescript
import { createContext, contexts } from '@scdevkit/service-bench-core';

const restContext = createContext(contexts.REST_CLIENT);

/**
 * Thin wrapper around the SB core REST context.
 * Mirrors the HttpService API shape used in the original leap-kit project.
 */
export class ApiService {
  private _host: HTMLElement;
  private _restClient = restContext.createConsumer(this._host);

  constructor(host: HTMLElement) {
    this._host = host;
  }

  async get<T>(path: string, params?: Record<string, unknown>): Promise<T> {
    const client = this._restClient.value;
    if (!client) throw new Error('[ApiService] REST client context not available');
    return client.get<T>(path, { params });
  }

  async post<T>(path: string, body: unknown): Promise<T> {
    const client = this._restClient.value;
    if (!client) throw new Error('[ApiService] REST client context not available');
    return client.post<T>(path, body);
  }

  async put<T>(path: string, body: unknown): Promise<T> {
    const client = this._restClient.value;
    if (!client) throw new Error('[ApiService] REST client context not available');
    return client.put<T>(path, body);
  }

  async delete<T>(path: string): Promise<T> {
    const client = this._restClient.value;
    if (!client) throw new Error('[ApiService] REST client context not available');
    return client.delete<T>(path);
  }
}
```
