# Service Bench — Experience API (NodeJS)

NodeJS Experience APIs expose a GraphQL endpoint to the Hasura supergraph. They are built on NodeJS using a schema + resolver pattern, deployed as FaaS.

| Path | Description |
|---|---|
| `src/` | Application code |
| `src/resolvers/` | GraphQL resolver implementations (one file per domain) |
| `src/resolvers/index.mjs` | Resolver registry — registers all Query and Mutation resolvers |

| `azure-pipelines-npm.yml` | CI/CD pipeline configuration |

## Creating a GraphQL Endpoint

Creating a GraphQL endpoint involves **3 steps**:

### Step 1 — Create a Resolver

Create a new file under `src/resolvers/` for your domain:

```js
// src/resolvers/my-feature.mjs
export const myFeatureResolvers = {
  Query: {
    get_myFeature: async (_, { id }) => {
      // business logic — call process API or return data
      return { id, name: "Example" };
    }
  },
  Mutation: {
    put_myFeature: async (_, { input }) => {
      // business logic
      return { success: true, id: input.id };
    }
  }
};
```

### Step 2 — Register in `src/resolvers/index.mjs`

```js
// src/resolvers/index.mjs
import { myFeatureResolvers } from './my-feature.mjs';

export const resolvers = {
  Query: {
    ...myFeatureResolvers.Query,
    // other query resolvers
  },
  Mutation: {
    ...myFeatureResolvers.Mutation,
    // other mutation resolvers
  }
};
```

### Step 3 — Register in `src/schema.mjs`

```js
// src/schema.mjs
import { gql } from 'graphql-tag';

export const typeDefs = gql`
  type MyFeature {
    id: ID!
    name: String!
  }

  input MyFeatureInput {
    id: ID!
    name: String!
  }

  type MyFeatureMutationResult {
    success: Boolean!
    id: ID
  }

  type Query {
    get_myFeature(id: ID!): MyFeature
  }

  type Mutation {
    put_myFeature(input: MyFeatureInput!): MyFeatureMutationResult
  }
`;
```

Refer to the sample code generated by the CLI template for complete examples.

## GraphQL Naming Convention

**All resolver keys must follow the naming prefix — PEP sidecar authorization depends on it:**

| Operation | Required prefix |
|---|---|
| Query | `get_` |
| Create mutation | `post_` |
| Update mutation | `put_` or `patch_` |
| Delete mutation | `delete_` |

## Security (OWASP / SC-IDP)

NodeJS Experience APIs must be protected against: Denial of Service, Broken Authorization, Batching Attacks, Insecure Configuration.

### Rate Limiting
Global ingress-level rate limiting is in place at Service Bench level. Pod-level resource controls also apply.

### PEP Sidecar Configuration

All queries and mutations must be protected by SC-IDP authentication and authorization. Configure in `env/<env>/properties.yml`.

The PEP sidecar:
- `authenticator` — validates bearer token via SC-IDP JWKS
- `activityLogger` — logs activity
- IntrospectionQuery marked as auth-free (Hasura needs schema access to build the supergraph — the regex only matches the exact legitimate Hasura introspection query)

```yaml
pep:
  config: |
    {
      "rules": [
        {
          "match": { "method": ["POST"], "body": "[\\s\\S]*?((post|get|put|delete|patch)_\\w*)[\\s\\S]*" },
          "handlers": [
            {
              "id": "authenticator",
              "config": {
                "jwks_uri": "<env-jwks-url>",
                "required_audience": [""]
              }
            },
            { "id": "activityLogger" }
          ]
        },
        {
          "match": { "method": ["POST"], "body": "<introspection-query-regex>" },
          "handlers": []
        },
        {
          "match": { "url": "/q/health/.*", "method": ["GET"] },
          "handlers": []
        }
      ]
    }
```

## Deployment & Hasura Onboarding

1. Deploy via ADO pipeline (`azure-pipelines-npm.yml`).
2. Wait ~10 minutes — the remote schema auto-registers in Hasura.
3. **Naming convention:** `55313` + sub-component-id + `_` + functionName (dashes → underscores, defined in `azure-pipelines-npm.yml`).
   - Example: namespace `55313-34-case-centre-plugin`, functionName `sb-case-centre-exp-api` → `_55313_34_sb_case_centre_exp_api`
4. Contact SB API team at `http://go/chat/sc-app-platform` if onboarding issues arise.
