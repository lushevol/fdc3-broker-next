# ScChat API Contract

## 1. Purpose

This document defines the runtime API contract for `sc-chat` in AG-UI mode, aligned with:

- AG-UI message concepts: https://docs.ag-ui.com/concepts/messages
- Current implementation in this repository (`ScChat`, `agUiAdapter`)

It covers:

- Component-to-host event contract (`sc-post`)
- Backend request contract for AG-UI mode
- Streaming response contract consumed by the component

---

## 2. Version And Compatibility

- Contract version: `1.0`
- Component scope: `sc-chat`
- Supported protocol values:
  - `ag-ui`

---

## 3. Message Model (AG-UI Aligned)

AG-UI defines a vendor-neutral `Message` model. This component currently uses a constrained subset.

### 3.1 Base Shape

```ts
interface BaseMessage {
  id: string;
  role: string; // AG-UI supports user/assistant/system/tool/developer/activity/reasoning
  content?: string;
  name?: string;
  encryptedContent?: string;
}
```

### 3.2 Message Roles Used By ScChat

`sc-chat` currently emits and consumes these conversation roles in its UI state:

- `user`
- `assistant` (mapped from internal `bot`)

### 3.3 Internal Mapping In ScChat

```ts
// Internal chat conversation -> AG-UI message
// user -> role: 'user'
// bot  -> role: 'assistant'
```

Notes:

- `system`, `tool`, `developer`, `activity`, `reasoning` are valid AG-UI roles, but are not generated by current `ScChat.ts` UI logic.
- `content` is currently plain string in this component. AG-UI multimodal `InputContent[]` is not produced by current `sc-chat` send flow.

## 5. AG-UI Backend Contract

## 5.1 Transport

- Method: `POST`
- Content-Type: `application/json`
- Accept: `text/event-stream`
- Transport client: `restClient.request(agUiApiName, agUiResource, ...)`

## 5.2 Request Body

```json
{
  "version": "1.0",
  "messages": [
    {
      "role": "user",
      "content": "<inputText>"
    }
  ],
  "metadata": {
    "model": "<selectedSource>",
    "<customKey>": "<customValue>"
  },
  "conversationId": "<conversationId>"
}
```

Notes:

- `version` is currently set to `1.0` by the component.
- `model` is injected by the component from current selected source.
- Other metadata fields come from the top-level `sc-chat` `metadata` property and are fully user-defined.
- Although AG-UI supports richer message content, current request uses text-only user input.

## 5.3 Streaming Response (SSE)

The component consumes `data:` lines and parses AG-UI events.

### Supported Event Types

- `TEXT_MESSAGE_CONTENT` -> append `delta` to bot message
- `TEXT_MESSAGE_END` -> mark completion
- `RUN_FINISHED` -> mark completion
- `RUN_ERROR` -> error path

### Backward-Compatible Event Types Also Accepted

- `message.delta` -> append `delta.text`
- `message.completed` -> completion
- fallback payload with `output.choices[0].delta.content`
- `output.id` prefixed with `STOP-` / `STOP-ERROR`

---

## 6. Error Contract

Common terminal error conditions:

- Non-2xx HTTP response
- Response body missing in stream mode
- AG-UI `RUN_ERROR`
- SSE parse failures

UI-level behavior in `ScChat.ts`:

- Replaces placeholder bot message with a user-visible error text
- Stops loading state and abort timer chain
